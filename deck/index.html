Six fictional employers. Real conversations. Zero stakes.

Open with the one-liner: every graduate faces their first interview, first awkward team lunch, first ambiguous task brief. WorkReady lets them rehearse all of it with AI characters in a fictional world — before a real employer is watching.

Graduates get one shot at learning how work works

  • Real placements are scarce and high-stakes
  • The hard parts are unwritten: interviews, inbox etiquette, team lunches, ambiguous briefs
  • Role-play with classmates isn't real enough to sting
  • Feedback arrives too late to help
  • Lecturers can't observe workplace behaviour
  • Students fear looking foolish — so they don't practise
The pain is emotional as much as practical: students freeze in interviews because they've never done one. The simulation gives them reps.

The whole arc, end to end

01Browse & apply on seek.jobs
02Resume outcome — with honest feedback
03Interview with the hiring manager
04Three work tasks + mid-placement coaching
05Team lunchroom — social presence
06Exit interview — scored on self-awareness

Every stage produces feedback the student can act on — and a record the lecturer can read.

Stage 6 is deliberately a different character (HR, not the hiring manager) so students feel safe being honest. Exit is scored on self-awareness, not performance.

Designed to be fail-safe, not fool-proof

  • Resumes get honest rejection feedback — strengths, gaps, what to fix
  • Interviews go badly sometimes; the debrief is specific, not crushing
  • Late task? The mentor notices, life goes on
  • Email a colleague badly? A comms coach scores tone & recipient choice
  • Every rejection unblocks another company — the world keeps moving

Rehearse the stumble, skip the scar.

The comms monitor is a hidden gem: every outgoing student message is scored for recipient appropriateness and tone. Teaching moment, not surveillance.

Privacy by design — not by policy

  • Students sign in with an issued access code — WR-XXXX-XXXX
  • Server stores no email, no name — code→person mapping lives with the lecturer
  • In-sim persona: students pick any name; mailbox derives from it
  • Uploaded resumes are redacted at import — emails, phones, addresses stripped
  • All mail & chat is in-sim fiction — nothing leaves the server
  • Codes are revocable, redemption fail-closed

The server can't leak what it never stored.

This lands well with privacy offices: unlinkability by construction, not by promise. The persona name is a stage name — fiction the student chooses.

This is the config-as-selling-point slide: pacing, hours, culture, social intensity — all env vars and data files. No code changes, no redeploy to change the calendar.

Built for the lecturer, too

  • Issue & revoke access codes in bulk — hand them out like a class list
  • Journey report: one printable page per placement — resume scores, interview transcript, task feedback, coaching notes, exit reflection
  • Inspect any student's inboxes, force outcomes, flush pending messages for teaching
  • No AI grading — the sim assesses; the lecturer grades
The journey report is the assessment artefact. Deliberately no aggregate AI mark — academics keep the judgement.

Runs on one box — or a hundred

  • Front-ends: static sites on GitHub Pages
  • Backend: one container, SQLite, no background workers — time is lazy-delivered
  • Scales to a cohort by adding students, not servers
  • Pluggable brain: stub (offline & deterministic) → ollama (local, free) → anthropic/openrouter
  • Every conversation surface degrades gracefully — the sim always runs
Demo-tier runs with zero API keys and no internet. Same code, one env var, upgrades to Claude-class conversations for production cohorts.
